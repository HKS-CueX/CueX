## 1. 本地实测与云端建模的边界声明

1. **本地实测事实（`.cuex-runtime/eval-latest.json`）** `[本地实测 Eval]`
   - 评测集：`6 / 6` 核心场景全部通过（精确率 `100.0%`、误打扰率 `0.0%`、撤回准确率 `100.0%`）。
   - 延迟表现：平均评估耗时 **`0.88 ms`**，P50 **`0.66 ms`**，P95 评估耗时 **`1.66 ms`**（6 个样本延迟：`1.66 / 0.77 / 1.44 / 0.41 / 0.37 / 0.66 ms`）。
   - 计算开销：在 `local_rule_zero` 确定性规则模式下，完成 `13` 次 System 1 规则评估与全部 6 个场景门控，消耗 **`0` tokens、`0` 次云端模型调用**。
   - 效用探索指标：`V = H − λI`（默认 `λ = 2`）在本轮 6 用例实测中为 **`+3`**。**边界说明**：`V = H − λI` 仍为探索性干预效用量化指标，尚未经过大规模真实用户盲测标定。
2. **Phase 3 实机 GPU ASR + 统一 CPA 模型网关校准** `[Phase 3 实机遥测]`
   - **ASR（Colab `NVIDIA RTX PRO 6000` 运行 `FunAudioLLM/SenseVoiceSmall + fsmn-vad`）**：`14/14` 条普通话/双语测试音频（`225.344s`）均耗时 **`52.57 ms`**（P95 **`89.59 ms`**），整体 **`RTF = 0.00327`**（约 `306×` 实时），平均字符错误率 `CER = 0.0867`（关键数字/定价测试片 `clip_04` `CER = 0.0`）。
   - **LLM 统一网关（`CpaProviderAdapter` 驱动 `gemini-4-hydrogen`）**：在 6 用例 S1 实测对标中，`gemini-4-hydrogen`（`reasoningEffort="low"`）取得 **`6/6 (100%)`** 精准分类（均值 `3,741 ms`；单次均值 `539` in / `264` out），显著优于 `gemini-3.5-flash-lite`（`4/6 = 66.7%`，均值 `1,521 ms`）；System 2 实测均值 `404` in / `1,115` out（含 `986` `reasoningTokens`），`12` 次全流水线实耗 **`15,399` tokens**（`provider_reported`，`0` 重试，代理未下发账单金额 `costFen = 0`）。
   - **实机校准结论**：将实测 `gemini-4-hydrogen` 单次输入/输出（含思维链 Token）代入单场 25 分钟模型，并**保守假设 System 1 与 System 2 全按高阶 S2 单价（`¥2.90 / ¥8.70` 每百万 Token）计价**，单场总 Token 为 **`46,357`**（仅较 Base `43,748` 高 `+6.0%`），单场 LLM `¥0.259`、全变动成本 `¥0.772`，**Pro 直接贡献率依然高达 `80.2%`（`Event 84.6%`）**——充分证实真正主导成本的是 **云端 ASR（`54.4%`）** 与 **免费补贴**，而非推理 Token！
3. **为什么不直接拿 0 Token 当作商业成本？** `[模型估算]`
   - 真实商业上台时，口语转写、长上下文语义对齐、深度追问召回与赛后复盘必须调用云端语音与语言模型。
   - 因此，我们将**“单场 25 分钟真实云端演讲”**拆解为 **10 项全要素可变成本**，基准情景单场模型消耗 **`43,748` Modeled Tokens**（保守情景 **`69,488`** Tokens，乐观情景 **`28,566`** Tokens），杜绝虚构不合理的 Token 节省百分比或纯 SaaS 高毛利假象。
4. **Phase 3 工程计费与收单边界** `[工程边界]`
   - 服务端现阶段已设计并实现 `UsageLedger`（用量账本）、`Entitlement`（权益校验）、`provider_unreported` 诚实计量标识与 `PaymentProviderAdapter` **沙盒契约**，但**尚未接入微信支付 / 支付宝真实商户生产环境**，当前无真实商业营收或实单付费账单。

## 2. 四层口径分离与核心指标定义

为防止商业讨论中混用不同分母或遗漏免费算力补贴，本模型严格区分以下四类经济指标与四类用户人群口径：

### 2.1 四类成本与利润口径
1. **`LLM Cost / Session`（纯模型调用成本）**：仅含 ① 文档解析、③ System 1 云端补判、④ System 2 深度推理、⑤ 单会话同前缀缓存扣减、⑥ 证据检索与 ⑦ 赛后复盘。**基准为 `¥0.098 / 场`**。
2. **`Full Var Cost / Session`（单场全要素可变成本）**：`LLM Cost` + ② 云端流式 ASR（`¥0.333 / 场`）+ ⑧ Web/WS/DB 基础设施摊销（`¥0.180 / 场`）。**基准为 `¥0.612 / 场`**，其中 ASR 占单场总成本 **`54.4%`**，是真正的第一成本项。
3. **`SaaS Gross Margin`（标准 SaaS 交付毛利率）**：扣除付费用户自身 `6` 场用量、退款算力损耗、支付通道费及人工客服后，不含免费获客体验补贴。**基准为 `92.2%`**（净营收 `¥57.82` − 付费 COGS `¥4.50`）。
4. **`Direct Contribution Margin`（含活跃免费补贴后的直接贡献率）**：再扣减按 `12:1` 算力活跃比摊派的免费用户算力补贴（`¥4.87 / 付费用户 / 月`）。**基准为 `83.8%`**（直接贡献 **`¥48.45 / 月`**）。

### 2.2 四层漏斗人群与分母规范（严禁用累计注册稀释补贴）

| 人群口径 | 英文标识 | 严格定义 | 成本核算用途 |
| --- | --- | --- | --- |
| **累计注册用户** | `registeredUsers` | 历史创建过账号的总池子 | 仅用于漏斗顶层盘点，**绝不作为**免费算力补贴分母 |
| **月活免费用户** | `freeMau` | 当月登录、浏览或编辑材料包的免费用户（含零语音消耗） | 用于观察活跃留存，不直接摊派 ASR/LLM 费用 |
| **月度算力活跃免费用户** | `activeFreeUsers` | 当月真实触发云端 ASR / LLM 彩排的免费用户 | **第 10 项补贴唯一法定分母**：按 `activeFreeUsers / paidUsers`（基准 `12:1`）计提 |
| **当月净付费活跃用户** | `paidUsers` | 当月持有有效 Event 或 Pro 权益且未全额退款的用户总数 | 净营收与分摊成本承载主体 |

## 4. 前缀缓存真实边界与支付退款规则核验

### 4.1 单会话同前缀缓存真相（无夸大共享假设）
- **仅计量单会话内同前缀复用**：本模型仅计算同一演练/演讲会话内部、相同材料前缀在连续轮次中的前缀缓存命中节省（Base `40%` 命中率、输入单价 `90%` 折扣，净节省 **`-¥0.020 / 场`**）。
- **明确排除虚假节流**：不存在跨槽位、跨模型或跨用户场景的 KV Cache 跨体共享（**NO cross-slot / cross-model / cross-scenario KV cache sharing**）。即便将第 5 项缓存命中率压降至 **`0%`**，Pro 直接贡献率仅微降 `0.5 pct`（见第 6 节敏感性测试 #6），证明商业可行性不依赖脆弱的缓存技巧。

### 4.2 支付通道拆分与退款政策（`2026-11-16` 核验）

| 支付通道 | 标准公开费率 | 特殊/虚拟类目风险区间 | 结算周期 | 官方退款手续费规则 | 官方信源与核验日期 |
| --- | --- | --- | --- | --- | --- |
| **微信支付 (WeChat Pay)** | **`0.60%`** `[云端公开费率]` | `0.60% – 1.00%`（小程序虚拟支付安卓端常见 `1.0%`，iOS IAP 另计） | 常规 `T+1` | 交易 `365 天` 内全额或部分退款（单笔最多 `50 次`部分退），**按等比原路退还对应手续费** | [微信支付官网](https://pay.weixin.qq.com) (`2026-11-16`) |
| **支付宝 (Alipay)** | **`0.60%`** `[云端公开费率]` | 优惠/小微 **`0.55%`**；特定数字虚拟/游戏类目可上浮至 **`1.00% – 1.20%`** | `T+1` / 实时余额（按签约） | 交易 `12 个月` 内主流标准收单产品**退款同步退回手续费**（部分老协议除外） | [支付宝商家中心](https://b.alipay.com) (`2026-11-16`) |

- **混合通道与净营收会计口径**：假设微信与支付宝各占 `50%` 交易额。
  - 基准情景：`0.60%` 混合通道费率，`2.0%` 假设退款率 -> Pro 净营收 **`¥57.82`**，Event 净营收 **`¥28.42`**。
  - 保守情景：按微信 `1.00%` 虚拟风险费率 + 支付宝 `0.80%`（混合 `0.90%`），`5.0%` 退款率且假设 `20%` 退款场景不可退回手续费，叠加 `50%` 已烧毁算力沉没成本。
  - 乐观情景：微信 `0.60%` + 支付宝小微优惠 `0.55%`（混合 `0.575%`），`1.0%` 退款率。

### 5.3 单用户承受上限 vs 公司盈亏平衡点（严格区分）
- **`maxAffordableSessionsPerProMonth`（单付费用户月可承受场次上限）**：在基准情景（扣减免费补贴与固定单客退款/通道损耗后，留给该用户自身消耗的净预算约 `¥52.12`，除以单场 `¥0.612`）下为 **`85 场/月`**；保守为 **`29 场/月`**，乐观为 **`211 场/月`**。配合 **月含 `240 分钟` 云端 ASR 硬配额上限（折合约 9–12 场正常演讲）**，单个重度用户极难把单户跑穿。
- **公司固定成本盈亏平衡点（`companyBreakeven`）**：
  > **状态：`UNMODELED` — 公司盈亏平衡点尚未测算（未纳入固定研发人力、市场费用与基础底座开销）。**
  > 计算公式保留为：`breakevenPaidUsers = fixedMonthlyCost / weightedMonthlyDirectContribution`（其中公司级月固定支出需在种子期商业化立项后另行核算）。本文档**不编造、不宣称**公司总体已达盈亏平衡。

### 5.4 LTV 简化公式的四项强制披露边界（`ltvCaveats`）
1. **年卡折让稀释未扣减**：当前简化公式 `LTV = 月直接贡献 × 平均留存月数`（基准 `¥48.45 × 7 = ¥339.15`）暂未扣减年卡 `¥499/年`（折合 `¥41.58/月`，约 `29.5%` 折扣）在真实付费结构中对混合 ARPU 的拉低效应。
2. **早期真实流失率待测**：虽然净营收已扣除 `1%–5%` 的退款率，但高时效答辩场景（如毕业季）在 M1–M3 之后的自然停用率可能高于通用效率工具，需在种子队列实测后重算分段留存曲线。
3. **获客错配营运资金**：`12:1` 算力活跃免费补贴在公式中由同期付费用户即期分摊；冷启动初期免费流量增长若早于付费转化 1–2 个月，会产生短暂的现金流错配垫资。
4. **CAC 为边际投放口径**：`CAC (¥18–¥45)` 仅覆盖内容投放、活动物料等边际获客支出，未摊销创始人研发工时与固定管理费用。
