> **诚实性声明**：本文档中所有价格档位、转化率假设、付费规模预测、CAC/LTV 估算及未来场景扩展均明确标注为 **`[商业假设 / 路线图规划]`**，目前 CueX 处于原型验证与比赛封版阶段，**尚未产生商业付费营收**。技术架构与功能现状严格对齐当前工程代码（`CueX Presentation` 为唯一已实现场景；`Social / Teaching / Sales / Custom` 处于协议注册与路线图阶段）。

## 1. 统一定位与首切场景选择逻辑

### 1.1 一句话品牌定位
- **品牌名**：**CueX**（英文全称 *CueX — Universal Cognitive Runtime*，中文副标 **「你的快思考外挂」**）
- **核心标语**：**「在深度思考之外，接住当下。」**（*Catch the moment beyond deep thinking.*）
- **核心机制**：围绕**最小必要干预（Minimum Necessary Intervention）**构建实时双系统认知外挂——通过独立受控的 `InterventionController`（`L0` 静默 / `L1` 边缘轻信号 / `L2` 轻量关键词提示 / `L3` 强纠偏/核查提示，配以 `TTL`、`contextVersion` 失效判定与自动撤回），帮助表达者在毫秒级临场分叉点保住节奏，而非用长段 AI 文本抢夺注意力。

### 1.2 为什么以 `CueX Presentation` 作为首个商业切口
虽然 `CueX` 的长期架构底座是面向任意高信息密度实时互动场景（`X` = Presentation / Social / Teaching / Sales / Custom）的通用认知运行时，但**商业启动必须先打透一个高痛点、快闭环、可度量的垂直切口**。我们选择 **`CueX Presentation（演讲与答辩临场引导师）`** 作为第一个已实现 MVP 与商业楔子，理由如下：

1. **前置材料结构最强，事实依据可验证**：创业路演、硕博开题/毕业答辩、产品发布会均天然附带 `.pptx` / `.pdf` / `.md` / `.txt` 讲稿或提纲，可由 `DocumentExtractor` 与 `PresentationCompiler` 在上台前编译为带唯一编号 `Evidence` 与章节序列（`PresentationCueSheetChapter` / `PresentationProgressNode`）的 `PresentationContextPack`（含一页式导播单 `PresentationCueSheet`），避免“无依据胡编”。
2. **分心容错最低，差异化价值最显性**：传统提词器在即兴 Q&A 时失灵；聊天型 Copilot（如 Cluely / Final Round AI 等常规大窗生成工具）输出大段文字逼迫用户低头阅读，反而导致眼神游离、念稿僵硬与语流中断。`CueX Presentation` 的 **Focus / Inspector 双视图 + L0-L3 分级撤回** 能让用户在 **60–90 秒演练对比** 中直观感受到“该闭嘴时绝对静默、卡壳越轨时给几个锚点词拉回”。
3. **传播具有天然社交证明（Built-in Demo Distribution）**：一次路演或一次答辩往往面向投资人、评委、导师或同侪观众，天然具备现场演示传播效应，符合 OPC 一人公司轻资产冷启动路径。

## 2. 优先级目标客户画像（P1 -> P2 -> P3）

遵循从“决策链最短、单次容错成本最高、最愿意为结果买单”向“规模化复购与团队扩展”递进的节奏：

| 优先级 | 目标客群 | 核心场景与高频时刻 | 核心痛点 | 推荐切入档位（假设） |
| :--- | :--- | :--- | :--- | :--- |
| **P1（首攻种子客群）** | **OPC 一人公司主理人、早期创业者、独立咨询顾问** | 融资/黑客松路演（如 5 分钟 Pitch + 2 分钟 Q&A）、B2B 关键客户提案、闭门方案评审 | 一人兼顾产品研发与商务沟通，准备时间碎；上台一紧张易漏掉关键数据、超时或被评委追问打乱主线；背死稿失去感染力 | `CueX Event`（按场买单）-> `CueX Pro`（月/年订阅） |
| **P2（规模扩张客群）** | **高校硕博研究生、科研汇报人、竞赛学生、青年学者** | 毕业论文答辩、开题/中期考核、学术会议口头报告、国奖/创新赛事答辩 | 学术术语、公式前提与实验对照组数据繁多，极怕答辩委员交叉追问时逻辑断裂或记混数值，对客观依据（Evidence）准确性极度敏感 | `CueX Free`（体验彩排）-> `CueX Event`（答辩季刚需转化） |
| **P3（生态复购客群）** | **企业技术讲师、方案架构师、专业培训师（及后续扩展场景主理人）** | 高频产品宣讲、大客户技术售前、内训课程交付；后期延伸至 `Teaching / Sales` 适配器 | 常态化多主题切换，需要长期记忆沉淀（如禁用词、个人语速偏置、常见高频 QA 库），团队内部需统一事实口径与复盘指标 | `CueX Pro` / `CueX Team`（规划中） |

## 3. 八要素商业画布（Business Model Canvas）

本节严格对齐竞赛与商业化审查要求的八大核心要素，确保八要素之间形成前后咬合的闭环：

| 画布要素 | CueX 核心设计（聚焦 `CueX Presentation` 首切场景 + 通用底座延展） | 商业/工程支撑锚点 |
| :--- | :--- | :--- |
| **1. 目标客户**<br>*(Customer Segments)* | **P1**：OPC 主理人、早期创业者、独立顾问；<br>**P2**：高校研究生/答辩学生/科研汇报人；<br>**P3**：解决方案专家、讲师及后续 `Teaching/Sales` 团队用户。 | 先抓“单次决策快、高痛点”的 P1/P2 个人用户，暂不重人力啃大企业长周期定制。 |
| **2. 客户痛点**<br>*(Pain Points)* | ① **背稿僵硬**：死记逐字稿丧失临场交流感；② **传统提词器脆弱**：即兴问答（Q&A）或跳页时滚动失灵；③ **现有 AI Copilot 太吵**：盲目吐大段答案抢占工作记忆，造成眼神飘忽与念稿破绽；④ **缺乏量化复盘**：讲完不知道哪里超时、哪里偏题、哪条提示真正帮到自己。 | 真实交互观测：普通大模型副驾驶高频插话会显著拉升说话者的认知负荷，反不如不提示。 |
| **3. 价值主张**<br>*(Value Proposition)* | **“在深度思考之外，接住当下。”**<br>只做**最小必要干预（L0–L3）**：平时保持 `L0` 克制静默；快要跑偏或遗忘关键论据时给出 `L1` 边缘信号或 `L2` 关键词/锚点句；发现事实口径冲突等高风险点时才触发 `L3` 强干预，并在讲者自行接回话题后**自动撤回（Auto-Withdraw）**。赛后以可量化的 `V = H - λI`（`λ = 2`）评估干预净效用。 | 协议层 `InterventionController` + `Evidence` 原文溯源 + `PresentationReflection` 闭环验证。 |
| **4. 交付成果**<br>*(Deliverables / Channels)* | ① **上台前**：多格式文档解析（`.pptx/.pdf/.md/.txt`）编译出的章节图谱、必讲锚点、证据库与可调 `MustSay/Anchor` 提示包；<br>② **演练/临场中**：极简低分心 `Focus` 临场视图 + 透明可观测 `Inspector` 调试视图 + `L0–L3` 实时决策流与自动撤回；<br>③ **散场后**：逐场结构化复盘报告（干预准确率、误打扰率、撤回统计、关键遗漏点、`V = H - λI` 净收益）及**显式授权确认后**方可写入的用户个人习惯记忆（`MemoryStore`）。 | 当前 `apps/web` 与 `apps/server` 已构建完整端到端 MVP 工作流。 |
| **5. 定价假设**<br>*(Pricing Hypotheses)*<br>*[全标注为假设]* | 采用“**免费体验 + 单场事件解锁 + 高频订阅**”阶梯转化，不强制低频用户包年：<br>• `CueX Free`：**¥0**（体验核心流式临场与基础编译，严格限制月度免费额度防毛利穿底）；<br>• `CueX Event`：**¥19–39 / 场**（高客单低频刚需：毕业答辩、单次关键路演/竞标全套包，包含无限次预演+正式临场+复盘）；<br>• `CueX Pro`：**¥59 / 月** 或 **¥499 / 年**（月度高频汇报者与创业者主力订阅）；<br>• `CueX Team`：**¥199 / 席位 / 月**（*规划中 Planned*：统一知识库口径、多席位配额与团队复盘面板）。 | 用 `Event` 承接“一年只答辩 1-2 次”的 P2 客群，用 `Pro` 锁住“每月多次宣讲”的 P1/P3 客群（参见 `UNIT_ECONOMICS.md` 盈亏模型）。 |

| **7. 获客渠道**<br>*(Acquisition Channels)* | ① **事件现场演示裂变**：黑客松路演、创投 Demo Day、高校答辩工作坊的实机演示与“一分钟极速救场”切片短视频；<br>② **OPC 与科研社群分发**：在独立开发者、一人公司（OPC）、硕博论文互助及咨询人社群提供“答辩/路演急救模板库（Pack Templates）”；<br>③ **生态合作渠道（中期规划）**：创业孵化器、高校就业与双创指导中心、企业培训服务商按团队包采购或分销导入。 | 零高额信息流买量前提下，优先靠“产品自传播切片 + 高痛点时间窗口（如答辩季 5-6 月 / 11-12 月）”启动冷获客。 |

### 为什么设计 `CueX Event（¥19–39/场）` 与 `CueX Pro（¥59/月）` 双轨并行？
1. **消除低频用户的订阅抗拒**：大量答辩学生和季度汇报型技术主管一年只有 2–4 次关键演讲，强推按月订阅会导致极高首月流失；按事件 ¥29 买断“保过一场核心答辩”，决策摩擦几乎为零，且在我们的全成本基准模型下**单场即可实现正向直接毛利贡献**。
2. **自然转化路径**：用户若在一个月内连续使用 2 次 `Event`（¥29×2 = ¥58），引导升级 `Pro（¥59/月）` 属于自然无痛升级，同时为 OPC / 培训师提供个人长期记忆沉淀粘性。
3. **防止 Free 羊毛穿底的财务护栏**：流式 ASR 与长耗时高频推理存在真实云端边际成本。因此 `CueX Free` 严格控制云端实时音频时长配额（或引导用户接入本地可控 ASR / 文本验证模式），将“免费获客成本”作为可控营销预算独立核算，不掩盖单用户盈利能力（详见 `UNIT_ECONOMICS.md`）。
